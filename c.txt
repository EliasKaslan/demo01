2. tag 命名规则：从「推断」变成「证实」
我上一轮说 nightly-releases-v0.27.1rc-a3 是 releases/v0.27.1rc 分支构建的 —— 当时这是推断（靠字符串形状 + 分支存在）。你问了之后我读了 CI 原始文件，现在是实锤。

.github/workflows/_schedule_image_build.yaml（release 镜像的合并/发布任务）：

yaml
复制
PATTERN="${{ inputs.branch_ref }}"
PATTERN="${PATTERN//\//-}"        # releases/v0.27.1rc → releases-v0.27.1rc
...
type=schedule,pattern=${{ steps.tag_pattern.outputs.pattern }},prefix=nightly-,suffix=${{ env.SUFFIX }}
type=pep440,pattern={{raw}},suffix=${{ env.SUFFIX }}
.github/workflows/schedule_image_build_and_push.yaml 给出 suffix ↔ 芯片对照：

json
复制
{name:"A2 Ubuntu",   suffix:""},              {name:"A3 Ubuntu",  suffix:"a3"},
{name:"310P Ubuntu", suffix:"310p"},          {name:"A5 Ubuntu",  suffix:"a5"},
{name:"A2 openeuler",suffix:"openeuler"},     {name:"A3 openEuler",suffix:"a3-openeuler"}, ...
两者相乘就精确复现了我给的每一条 tag：nightly- + main + -a3 = nightly-main-a3；nightly- + releases-v0.27.1rc + -a3 = nightly-releases-v0.27.1rc-a3。

同一份文件还解释了「为什么 v0.27.1rc-a3 不存在」：只有 type=pep440 那条规则（on: push tags: v*）才会产出不带 nightly- 前缀的裸版本 tag。0.27 还没打过 v* tag，所以这个形状的 tag 根本没人建过 —— 这不是猜的，是 CI 规则决定的。

另外这份文件顶部写明：镜像其实是在 SWR（swr.cn-north-12.myhuaweicloud.com/ascend/vllm-ascend）构建并合并多架构，再由 sync-tools 同步到 quay.io。所以 quay.io 是镜像站，Docker Hub 的 ascendai/ 是又一层镜像 —— 三者 digest 一致。

## 1. 引言

### 1.1 编写目的

本文档基于对 vllm-ascend 仓库中 Kimi-K3（下称 K3）适配代码的逐文件分析，说明：

1. Kimi-K3 模型的结构特点及其对推理框架提出的新需求；
2. vLLM-Ascend 插件如何在昇腾 NPU（Atlas 800 A2 / A3、Ascend 950）上适配并运行 K3，包括模型注册、配置、混合注意力（KDA + MLA）、MoE/SiTU、量化、多模态、前端解析、投机解码、PD 分离等全部适配点的设计与实现；
3. 如何部署运行该模型：环境准备、编译安装、启动命令、功能/精度/性能验证方法。

预期读者：推理框架开发工程师、昇腾适配工程师、部署与测试工程师。

### 1.2 项目背景

Kimi K3 是月之暗面（Moonshot AI）发布的开源权重原生多模态 Agentic 模型，总参数 2.8T、激活参数 104B，是首个开源的 3T 级模型。它引入了多项 vLLM 主线（v0.26.0）尚未内置的新架构要素：

- **KDA（Kimi Delta Attention）线性注意力**：门控 Delta Rule 类线性注意力，取代大部分 softmax 注意力层；
- **周期性 Gated MLA**：每隔若干层插入一层带输出门控、无 RoPE 的多头隐式注意力；
- **AttnRes（Attention Residuals）**：跨层"块残差流"学习加权混合，替代普通单流残差；
- **Stable LatentMoE**：896 专家 top-16 + 2 共享专家，专家在 3584 维隐空间内计算；
- **SiTU-GLU 激活**：新的有界门控激活函数；
- **原生 MXFP4/MXFP8 量化感知训练（QAT）**权重；
- **MoonViT-V2 视觉编码器**（401M 参数）与 1M token 上下文；
- **XTML 对话协议**：无 Jinja chat template，由 tokenizer 自带 Python 编码器（`encoding_k3.py`）渲染。

上游 vLLM v0.26.0 仅内置了 K3 的文本前身 `KimiLinearForCausalLM`（`vllm/model_executor/models/kimi_linear.py`），**没有** `KimiK3ForCausalLM` / `KimiK3ForConditionalGeneration` 架构、没有 K3 的 XTML renderer/parser 栈；transformers 也未发布 K3 配置类。因此 vLLM-Ascend 以 **OOT（out-of-tree，插件带外注册）** 方式完成了 K3 的完整适配：主特性提交 `23cfbd5ba`（[Feature][v0.26.0rc] Support Kimi K3 on Ascend, #12950，+35410 行）一次性落地模型、算子、量化、多模态、前端与 KV 传输，后续提交（#13277、#13507、#13509、#13520、#13836、#13989 等）持续补充投机解码、性能融合与前端对齐。

### 1.3 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| KDA | Kimi Delta Attention，K3 的线性注意力，gated delta rule 变体，含短卷积与循环状态 |
| MLA | Multi-head Latent Attention，多头隐式注意力（DeepSeek 系列引入），K3 使用无 RoPE + 输出门控变体 |
| AttnRes | Attention Residuals，K3 的块残差混合机制（`attn_res_block_size=12`） |

| PD 分离 | Prefill/Decode Disaggregation，P 节点算 prefill、D 节点算 decode，KV 经 Mooncake 传输 |
| ACL Graph | 昇腾上等价于 CUDA Graph 的图执行模式（`cudagraph_mode: FULL_DECODE_ONLY`） |
| AscendC | 昇腾自定义算子开发语言（csrc 目录下 op_host/op_kernel） |
| aclnn | 昇腾算子调用接口（CANN NN 加速库调用协议） |
| Triton-Ascend | 昇腾后端的 Triton（triton-ascend 包），用于写融合 kernel |
| A2 / A3 / A5 | Atlas 800 A2（910B，soc 220-225）/ Atlas 800 A3（910C，soc 250-255）/ Ascend 950（soc 260，代码中枚举名 A5） |
| GDN | Gated Delta Net，vLLM 中线性注意力的通用实现基座（KDA 复用其 mamba 类状态管理） |
| QuaRot | 旋转量化技术；ModelSlim 对 K3 FP4 激活做旋转变换后再 INT4 推理 |
| NZ / weightnz | 昇腾 FRACTAL_NZ 权重排布（矩阵乘加速格式） |

## 2. 需求分析

### 2.1 Kimi-K3 模型结构剖析

#### 2.1.1 官方模型摘要（模型卡）

| 维度 | 参数 |
| --- | --- |
| 总参数 / 激活参数 | 2.8T / 104B |
| 层数 | 93（69 层 KDA + 24 层 Gated MLA，第 0 层为 dense，其余为 MoE） |
| 隐层维度 / 注意力头数 | 7168 / 96 |
| KDA 配置 | head_dim=128，short_conv_kernel_size=4，use_full_rank_gate=true，gate_lower_bound=-5.0 |
| MLA 配置 | kv_lora_rank=512，q_lora_rank=1536，qk_nope_head_dim=128，qk_rope_head_dim=64（保留但不旋转，`mla_use_nope=true`），v_head_dim=128，`mla_use_output_gate=true` |
| MoE | 896 路由专家 top-16 + 2 共享专家；Latent MoE 维度 3584，每专家中间维 3072；sigmoid 路由 + noaux_tc（无辅助损失，带 e_score_correction_bias），renormalize |
| AttnRes | attn_res_block_size=12 |
| 激活函数 | SiTU-GLU（hidden_act="situ"，activation_situ_beta=4.0，activation_situ_linear_beta=25.0） |
| 词表 / 上下文 | 163840 / 1048576（1M） |
| 视觉 | MoonViT-V2，27 层，hidden 1024，patch 14，sd2_tpool 2×2 合并，patchmergerv2 投影到 7168 |
| 量化 | 原生 MXFP4 权重 / MXFP8 激活（QAT）；社区 ModelSlim W4A8 量化版 |
| 模态 | 文本、图像（vllm-ascend 当前实现不支持视频输入） |

#### 2.1.2 本地减层验证权重（bf16）

`D:\workspace\Kimi-K3减层bf16权重` 为按层裁剪的功能验证版（非精度验证版）：

- `num_hidden_layers=4`：layer0 = dense MLP（`first_k_dense_replace=1`），layer1~3 = KDA（`kda_layers=[1,2,3]`，1-based），layer4（即 idx=3）= MLA（`full_attn_layers=[4]`，1-based；`is_kda_layer` 判定 `(layer_idx+1) in kda_layers`）；
- 专家规模保留 896/top-16/2 共享，MoE 结构与全量一致；
- bf16 未量化 → 走 **非量化 MoE MLP 路径**，需要 `7f158640c`/本地 `75c1fe22a` 的 SiTU 修复（原代码在非量化路径对 SiTU 抛 `NotImplementedError`）；
- 附带完整的 K3 官方 tokenizer/processor/modeling 代码（`tokenization_kimi.py`、`encoding_k3.py`、`kimi_k3_processor.py` 等），`--trust-remote-code` 加载。

#### 2.1.3 KDA 递归公式（recurrent_kda README）

每 token 状态更新（gated delta rule）：

```text
S = exp(gate_t) · S                      # 状态衰减
delta = beta_t · (v_t − S @ k_t)         # delta 修正
S = S + outer(delta, k_t)                # 状态更新
o_t = S @ (q_t · scale)                  # 输出
```

其中 `gate = lower_bound · sigmoid(exp(A_log)·(g + dt_bias))`（safe_gate=True，lower_bound=-5.0），kernel 内做 q/k L2 归一化与 beta sigmoid。状态 S 为每头 `[K,V]=[128,128]` 矩阵（fp32），prefill 用 chunk 并行算法（`chunk_kda_fwd`，chunk_size∈{32,64,128}），decode 用逐步递归（`recurrent_kda`）。

#### 2.1.4 SiTU 激活（vllm_ascend/ops/activation.py）

```text
gate' = β · tanh(gate/β) · sigmoid(gate)          # β = 4.0
up'   = β_lin · tanh(up/β_lin)                    # β_lin = 25.0（可选）
out   = gate' · up'
```

与 SiLU/SwiGLU 的区别：gate 支路用有界 soft-tanh 调制替代无界恒等映射，up 支路再做一次有界 tanh 压缩，抑制 MoE 大规模专家下的激活离群值（"Stable" LatentMoE 的稳定性来源之一）。

### 2.5 能力差距分析（为什么必须做这些适配）

| 差距 | 现状（vLLM v0.26.0 / transformers） | K3 需求 | 适配结论 |
| --- | --- | --- | --- |
| 模型架构缺失 | registry 只有 `KimiLinearForCausalLM`（文本、无 AttnRes/无输出门/无 LatentMoE 隐空间 dispatch） | 多模态 K3（视觉塔+投影器+占位符展开） | OOT 注册两个新架构，复用 KimiLinear 的 GDN 基座类名触发 PluggableLayer 替换 |
| 配置类缺失 | transformers 不带 `kimi_k3`/`k3_dspark` model_type；checkpoint 用 auto_map 远程代码 | 不执行 checkpoint 远程代码也能加载（安全+稳定） | 插件内置 Config 类并注册到 `_CONFIG_REGISTRY` 与 `AutoConfig` |
| KDA 算子缺失 | vLLM 有 GDN triton 路径（kimi_linear），NPU 上无 KDA 专用高性能算子 | chunk/recurrent KDA、gate cumsum、layout swap 均需 NPU 化并支持 ACL Graph/投机解码 | 新增 4 个 AscendC 算子（含 arch35 特化）+ Triton 融合 kernel，torch_binding 注册含 Meta 实现 |
| MLA 差异 | 昇腾 MLA 路径假定有 RoPE（DeepSeek 系） | no-RoPE + 输出门控 + 12 头（A5 prolog 需 16 头） | mla_v1/device_op 增加 use_mla_rope 开关、g_proj 门控、A5 head padding |
| MoE 激活缺失 | fused_moe 只支持 silu 等标准激活 | SiTU-GLU + 隐空间 dispatch（3584）+ 896 专家 | activation.py 新增 SituAndMul；FusedMoE 增加 routed_input/output_transform 挂点；非量化路径修复（7f158640c） |
| 量化格式 | compressed-tensors/ModelSlim 已有框架 | K3 原生 MXFP4/MXFP8 + ModelSlim W4A8（QuaRot 旋转、weightnz、latent 投影量化） | w4a16_mxfp4/w4a8_mxfp4/modelslim_config/compressed_tensors_config 扩展映射 |
| 前端协议 | vLLM 0.26 无 K3 XTML renderer/parser（上游 #50093/#50420/#50540/#50886 未进 pin 版本） | XTML think/response/tools 通道、reasoning_effort、无 Jinja 模板 | 全套 monkey-patch：renderer/parser/structural tag/media connector，行为对齐上游已合入实现 |
| 投机解码 | DSpark 框架已有（DeepSeek V4/Qwen3），无 K3 草稿模型 | K3 MLA DSpark 草稿（markov_rank、非因果 draft attention、YaRN） | 新增 K3DSparkForCausalLM + proposer 扩展 + 辅助图捕获 |
| 混合缓存 PD 传输 | Mooncake/AscendStore 只处理同构 KV | KDA conv/recurrent 状态 + MLA KV 异构、非等 TP | connector 增加 linear_attn_config 分支与 2M 对齐基址恢复 |

### 2.6 约束与假设

1. vLLM 版本被 pin 在 v0.26.0（commit d02df748），所有 patch 以该版本为基线；上游后续合入 K3 前端后（PR #50093 等），插件 patch 需按 `patch/__init__.py` 登记逐项回收；
2. K3 的 tokenizer/图像处理器契约由 checkpoint 目录内官方 Python 文件（`tokenization_kimi.py`、`encoding_k3.py`、`kimi_k3_processor.py` 等）提供，需 `--trust-remote-code`；TIKTOKEN_CACHE_DIR 建议预热缓存；
3. TP 大小必须整除注意力头数（96），且影响 KDA 状态布局与专家放置；
4. 视频输入不支持（当前仅图像）；Responses API 对 K3 显式禁用（仅 Chat Completions）；
5. 自定义算子编译（COMPILE_CUSTOM_KERNELS=1）需 gcc>8/C++17，A3 构建需 git submodule（CANN 算子依赖库）；构建产物与 SoC 绑定（`check_ascend_device_type` 会校验运行时芯片与编译目标一致）。

### 3.2 关键设计策略

1. **OOT 注册而非修改 vLLM**：K3 模型、配置、processor 全部通过 vLLM 插件机制（`ModelRegistry.register_model`、`_CONFIG_REGISTRY`、`AutoConfig.register`）注入，vLLM 本体零修改；对 vLLM 行为差异（前端、投机配置、KV 协调器）用集中登记的 monkey-patch（`patch/platform/*`）弥合，并标注上游 PR 与移除计划。
2. **复用 GDN 基座 + PluggableLayer 替换**：KDA 层按上游注册类名 `KimiGatedDeltaNetAttention` 实例化，由 `register_ascend_customop` 将其替换为 `AscendKimiGatedDeltaNetAttention`（`ops/kimi_kda.py`），从而复用 vLLM 的 mamba 状态管理（cache 分配、copy func、prefix caching）而只重写计算路径。
3. **chunk/recurrent 双路径 + 容量型状态池**：prefill 用 chunk 并行算子，decode 用递归算子；状态池按容量组织、以 device 端索引寻址（packed `[T]` 或投机 `[seq_num,max_step]`），host 不读设备值 → 兼容 ACL Graph 捕获与 DSpark 回滚（`num_accepted_tokens`）。
4. **隐空间 MoE**：FusedMoE 挂 `routed_input_transform`（7168→3584 down_proj）与 `routed_output_transform`（norm+up_proj 3584→7168），使 dispatch/combine 通信量减半，专家在 3584 维隐空间计算（Stable LatentMoE 语义与 checkpoint 权重形状一致）。
5. **算子融合优先，纯 PyTorch 兜底**：Triton 可用时走 fused norm-gate / attention-residual / SiTU 融合路径，不可用时回退 torch_npu 组合算子（`HAS_TRITON` 分支），保证 A2/A3/310P 兼容面。
6. **量化路径分层**：原生 MXFP4（compressed-tensors）与 ModelSlim W4A8（QuaRot + weightnz + dequant_situ_quant 融合）分别映射；latent 投影仅在 ModelSlim（quant_config 名 "ascend"）下量化；视觉塔对 compressed-tensors 配置强制忽略（保持 bf16）。
7. **前端对齐上游语义**：XTML 协议常量、reasoning/tool parser、renderer 行为以"上游已合入 PR"为准绳（#13520 复核 vLLM main d8f840071），未合入语义不提前实现，降低后续升级成本。
